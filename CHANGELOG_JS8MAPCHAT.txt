JS8Map — Version History
==================================================

NOTE ON VERSION NUMBERS -- this changelog changes schemes at the 1.6.0 line:
  - Entries BELOW (v1.80 .. v1.83) are JS8Map's own build lineage, pre-unification.
  - From #35 (2026-07-15) onward this changelog tracks the PRODUCT version:
    _APP_VERSION_STR in JS8Map.py = "1.6.0" -- the same number JS8FastChat reports.
    Both exes display and log "JS8MapChat 1.6.0".
  - The v1.83 Linux/cross-platform work is INSIDE 1.6.0 (rolled up, not
    superseded) -- this single JS8Map.py carries both.
  - Companion changelog: JS8FastChat Ver 1.5\CHANGELOG.txt. See the architecture
    doc for how the two apps fit together.
  Scheme change is deliberate. STATUS: unification recorded, PROVEN (the exe
  logs version : 1.6.0).

JS8MAP SPOTTER Ver 1.1   build 2026-10-15a   "cleanup + Linux prep"
  SEC   Request token: every POST from the map page carries a secret
        (X-JS8Map-Token, from boot.js JS8MAP_BOOT.req_token); the server
        refuses POSTs without it (403). Stops another website open in the
        browser from making JS8Call send / transmit. Secret kept in the data
        folder (js8map_request_token.txt) and reused, so long sessions and
        restarts are unaffected. /raise_window (FastChat) stays open.
        "Access-Control-Allow-Origin: *" removed from POST / OPTIONS replies.
        Off switch: "require_request_token": false in ham_map_config.json.
        Design + undo: project doc "request token (TX protection)".
  FIX   Thread safety: build_payload no longer reads store._last_lost (a
        side channel shared between requests); the rev counter is locked.
  PERF  Web server is threaded (a slow FCC lookup no longer stalls the
        page's polls); POSTs still run one at a time.
        /statrep.json?rev=: unchanged store -> {"unchanged":true} (about
        0.3 KB instead of the full payload); full refresh at least once a
        minute so ages and dimming keep moving.
  LINUX All text files LF line endings (.bat/.iss stay CRLF); scripts
        executable. New debug.sh (run from source; checks for python3-tk).
        Crash log in ~/.local/share/JS8Map on Linux (was /tmp). Default-
        browser fallback no longer tries os.startfile first. JS8Spotter
        database also searched in ~/Applications, ~/.local/share, ~/bin, /opt.
        Verified: runs from source on Linux (Python 3.12, Tk 8.6), connects,
        decodes StatRep / F!104 / band-activity QSO, map page works.
  TEST  tests/test_core.py -- 22 regression tests (python -m unittest
        discover -s tests). tools/fake_js8call.py -- stand-in JS8Call API

  CLEAN Unused imports removed from JS8Map.py (about 70) and js8map_statrep;

    name 'JS8MapChat Shared'; the legacy 'JS8MapChat Shared Ver 1.5' is still

    of the name means the next bump never touches the contract.
